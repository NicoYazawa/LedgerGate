## 2. Service catalog

| Service | Owns | Synchronous responsibilities | Asynchronous responsibilities |
|---|---|---|---|
| `gateway` | `gateway` DB: request log, settlement outbox | Auth via Redis key cache; `Reserve` on ledger; upstream call; SSE proxy; usage extraction; failover before first token | Publish `usage.recorded`; retry settlement outbox |
| `control` | `control` DB: accounts, workspaces, users, API keys, sessions, audit | Admin BFF; identity CRUD; RBAC; React UI | Publish `apikey.created/revoked` |
| `ledger` | `ledger` DB: ledger accounts, wallet balances, ledger entries, reservations, settlements, usage attempts, credit lots | `Reserve`, `Release`, `Settle`; balance and invariant checks | Consume `usage.recorded`, `price.snapshot`, `payment.*`; publish `settlement.completed` |
| `billing` | `billing` DB: price catalog, price snapshots, plans, subscriptions, grant policies | Admin price/subscription CRUD; rating rules | Publish `price.snapshot`, `subscription.granted` |
| `payment` | `payment` DB: payment intents, top-ups, refunds, webhook events, PSP settlements, FX rates | Checkout, refund, webhook verification | Publish `payment.succeeded/refunded` |
| `reconcile` | `reconcile` DB: runs, items, adjustments | Admin reconciliation views | Consume usage/settlement/payment events; run provider/PSP/ledger comparisons |

Rules:

- Each service owns exactly one database. No cross-database joins or transactions.
- The Postgres instance is shared for local ergonomics; production can split it per service without changing ownership.
- HTTP/JSON + OpenAPI between services; every service call carries a per-service bearer token.
- NATS JetStream carries asynchronous facts; Postgres outbox is the source of those facts.

## 3. Money path

See [`diagrams/money-path.puml`](diagrams/money-path.puml).

1. gateway authenticates the API key from the Redis cache.
2. gateway calls `ledger.Reserve` synchronously with a request id and idempotency key.
3. On insufficient balance, return 402 without calling an upstream.
4. On success, call the upstream and stream SSE to the client, extracting usage.
5. On client disconnect, keep reading briefly for usage; otherwise estimate.
6. Write a settlement intent to the gateway outbox, return the response, and publish `usage.recorded` durably.
7. ledger consumes the event, rates from the latest billing price snapshot, writes double-entry postings, and releases the hold idempotently.
8. If the upstream fails before the first token, release the reservation. If all attempts fail, release.
9. Failover is allowed only before the first token. Every attempt is recorded; the user is charged once.

Failure semantics:

- Zero output or failure before first token: user charge 0; any upstream cost is platform COGS.
- Client disconnect: charge generated tokens; prefer provider usage, otherwise estimate.
- Failover: user charged once for the successful attempt; all attempt costs recorded.
- All attempts fail: user charge 0; reservation released.
- Settlement is at-least-once; `settlement_id` and `(logical_request_id, attempt_no)` are unique.
- Reservation expires after 30 minutes; a sweeper releases orphaned holds.

## 4. Top-up, refund and FX

See [`diagrams/topup-refund.puml`](diagrams/topup-refund.puml).

Currency model:

- Ledger base currency is USD, stored as integer micro-USD.
- CNY is a presentment currency. Top-ups record presentment amount, settled USD, FX rate and PSP fee.
- One wallet per workspace, denominated in USD. No dual-currency wallet.
- Refunds use the original transaction FX rate; differences go to the FX gain/loss account.

## 5. Data ownership

| Database | Tables (initial) |
|---|---|
| `gateway` | `request_log`, `settlement_outbox` |
| `control` | `accounts`, `workspaces`, `users`, `workspace_members`, `api_keys`, `sessions`, `audit_log` |
| `ledger` | `ledger_accounts`, `wallet_balances`, `ledger_entries`, `reservations`, `settlements`, `usage_attempts`, `credit_lots` |
| `billing` | `price_catalog`, `price_snapshots`, `plans`, `subscriptions`, `grant_policies` |
| `payment` | `payment_intents`, `topups`, `refunds`, `webhook_events`, `psp_settlements`, `fx_rates` |
| `reconcile` | `reconciliation_runs`, `reconciliation_items`, `adjustments` |

Invariants:

- Every ledger transaction balances: sum(debits) = sum(credits).
- `wallet_balances.balance = sum(ledger_entries)` for the wallet account.
- `available = balance - held`; `held >= 0`.
- A reservation transitions `held -> settled | released | expired` exactly once.
- Every settlement references an immutable price snapshot.
- Every logical request is charged at most once; retries and failovers create attempts, not charges.

## 6. Cross-cutting conventions

| Topic | Decision |
|---|---|
| IDs | UUIDv7 for database keys and event IDs |
| Money | `BIGINT` micro-USD; no floating point |
| Time | UTC `timestamptz`; display in local timezone |
| Gateway ingress | OpenAI-compatible only; Anthropic is an upstream adapter |
| Internal APIs | OpenAPI-first with `oapi-codegen`; HTTP/JSON |
| Service auth | Per-service bearer tokens; mTLS is a later upgrade |
| API keys | Random high-entropy token, `lg_` prefix; HMAC-SHA256 with server pepper; show prefix + last four |
| Provider keys | AES-256-GCM; KEK from environment / cloud secrets |
| Admin auth | Email + password (Argon2id); session cookie (HttpOnly/Secure/SameSite) + CSRF |
| Config | Environment variables + YAML defaults + compose secrets |
| Observability | OTel traces, Prometheus metrics, Grafana dashboards, `slog` JSON |
| Content storage | Metadata only by default; no prompt/response bodies |
| Testing | High-seam integration via HTTP APIs; testcontainers; mock upstream; property-based ledger tests |

## 7. Non-goals relevant to architecture

- No real production payment processing, tax, invoices, or accounting periods.
- No BYOK.
- No embeddings, images, audio, Realtime, Batch, or fine-tuning.
- No Anthropic-native ingress.
- No Anthropic vision in the MVP; text + tool calling only.
- No mid-stream failover, dynamic cost/latency routing, semantic cache, guardrails, or stream replay.
- No SSO/SAML, multi-region, day-one K8s, or 99.99 SLA.
- No prompt/response content storage by default.
